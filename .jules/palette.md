## 2024-05-17 - aria-label Overriding Inner Content
**Learning:** Adding an `aria-label` to an interactive element (like `role="button"`) completely overrides its inner content for screen readers. In the Prompt Machine app, adding `aria-label="Tap to copy this prompt"` to the main card prevented screen readers from ever reading the actual prompt text inside it.
**Action:** Use `aria-describedby` linked to external hint text instead of `aria-label` when an element contains important dynamic text that must be read by screen readers.
## 2024-05-18 - Reliable Screen Reader Announcements for Transient Toasts
**Learning:** In interactive web applications, relying solely on CSS opacity transitions to show/hide status text (like "Copied") inside an `aria-live` region often fails to reliably trigger screen reader announcements on consecutive interactions. Screen readers generally monitor DOM text/content mutations, not visual styling changes. Leaving visually hidden text in the DOM can also pollute the accessible name of parent interactive elements.
**Action:** When implementing transient toast notifications within `aria-live` regions, ensure the actual text content of the element is removed or emptied from the DOM after the visual fade-out transition completes. This clears the state so that the next time the same message needs to be announced, injecting the text back into the element will register as a new mutation and be reliably announced.
